# سند پروژهٔ هم‌سخن

آخرین به‌روزرسانی: ۱۰ آبان ۱۴۰۵ (۲۰۲۶-۱۱-۰۱)، نسخهٔ ۱٫۰٫۰

## معماری

| بخش | فناوری | چرا |
|---|---|---|
| اپ | React 19 + Vite + TypeScript + Tailwind 4 | طرح UX Pilot با Tailwind نوشته شده بود؛ وفاداری به آن ساده‌تر است |
| مسیریابی | `createHashRouter` | روی GitHub Pages بدون تنظیم سرور، همهٔ مسیرها کار می‌کنند |
| دادهٔ کاربر | IndexedDB (`idb`) در پایگاه `hamsokhan` | بدون حساب و سرور؛ آفلاین |
| تنظیمات نمایش | `localStorage` (`hamsokhan.settings`) | پوسته پیش از نخستین نقاشی صفحه اعمال شود |
| PWA | `vite-plugin-pwa` (generateSW، `registerType: prompt`) | نصب، آفلاین، و به‌روزرسانی فقط با رضایت کاربر |
| هوشواره | Firebase Functions v2 + `@anthropic-ai/sdk` + Firestore | کلید فقط در Secret Manager؛ سقف‌ها در Firestore |
| قرارداد مشترک | `shared/` (zod) | اپ و سرور یک تعریف از درخواست و پاسخ دارند |

### جریان یک توضیح

۱. کاربر بیتی را انتخاب می‌کند. این کار درخواستی نمی‌فرستد.
۲. کاربر «این بیت را توضیح بده» را می‌زند. اگر بار اول باشد، یادداشت ارسال داده نمایش داده می‌شود. بعد فقط بخش «معنی ساده» درخواست می‌شود.
۳. هر بخش دیگر (واژه‌ها، ساختار، دستور، آرایه‌ها، برداشت عمیق‌تر) فقط وقتی کاربر آن را باز کند درخواست می‌شود.
۴. سرور:
   - Origin، اندازه و ساختار درخواست را بررسی می‌کند.
   - سقف هر IP را می‌شمارد.
   - برای شعر کتابخانه، متن را از نسخهٔ خودش برمی‌دارد و هش متن را تطبیق می‌دهد.
   - حافظهٔ مشترک را نگاه می‌کند (فقط برای شعر کتابخانه).
   - سقف روزانه را می‌شمارد و Claude را با خروجی ساختاریافته صدا می‌زند.
   - خروجی را با zod اعتبارسنجی و ارجاع واژه‌ها را لنگر می‌کند.
۵. اپ پاسخ را دوباره اعتبارسنجی می‌کند و در IndexedDB نگه می‌دارد. باز کردن دوبارهٔ همان بخش هزینه‌ای ندارد.

### لنگر کردن شاهدها به متن

- هر مصرع با فاصله‌ها به «توکن» تقسیم می‌شود. نیم‌فاصله واژه را نمی‌شکند.
- مدل بیت را با توکن‌های شماره‌دار می‌بیند و برای هر شاهد این‌ها را برمی‌گرداند: شمارهٔ مصرع، اولین و آخرین توکن، و عین عبارت.
- سرور (`shared/text.ts` → `resolveAnchor`) بررسی می‌کند که عبارت با همان توکن‌ها یکی باشد. مقایسه با `searchKey` انجام می‌شود که اعراب، ی/ي، ک/ك و نیم‌فاصله را یکسان می‌کند.
- اگر شماره‌ها غلط باشد ولی عبارت فقط یک‌جا در بیت بیاید، جای درست جایگزین می‌شود. اگر عبارت مبهم یا ناموجود باشد، شاهد بدون لنگر و با برچسب «جای دقیق نامعلوم» نمایش داده می‌شود.
- واژهٔ تکراری با شمارهٔ توکن از تکرار دیگرش جدا می‌شود. آفست‌ها روی رشتهٔ اصلی و به واحد UTF-16 هستند.

## مدل داده (IndexedDB، نسخهٔ ۱)

| مخزن | کلید | محتوا |
|---|---|---|
| `userPoems` | `id` (`u-<uuid>`) | شعر واردشده: بیت‌ها، عنوان و شاعر اعلام‌شده، `textVersion` |
| `savedPoems` | `poemId` | شعرهای ذخیره‌شده |
| `savedVerses` | `poemId#n` | بیت‌های ذخیره‌شده |
| `analyses` | `poemId\|textVersion\|n\|section\|promptVersion` | توضیح‌های دریافت‌شده (با مدل و برچسب نمونه) |
| `progress` | `poemId` | آخرین بیت خوانده‌شده |
| `conversations` | `poemId#n` | گفت‌وگوی هر بیت (با `textVersion`، تا گفت‌وگوی متن قدیمی قاطی نشود) |
| `reflections` | `id` | برداشت‌های شخصی و بازخورد |
| `meta` | `key` | رضایت یادداشت ارسال داده، آمار مصرف این دستگاه |

- پشتیبان JSON: `{ app: "hamsokhan", schema: 1, exportedAt, data }`.
- ادغام: هیچ رکوردی حذف نمی‌شود و از هر رکوردِ دوطرفه، نسخهٔ تازه‌تر می‌ماند. گفت‌وگوها پیام‌به‌پیام ادغام می‌شوند.
- Firestore (فقط سرور): `hooshvareUsage/{روز}`، `hooshvareRate/{ipHash_بازه}`، `hooshvareCache/{sha256}`، `hooshvareReports`، `hooshvareConfig/ipSalt`. IP فقط به‌صورت هش نمک‌دار ذخیره می‌شود.

## تصمیم‌ها و فرض‌ها

- **رنگ تأکید:** سبز طرح (#214D3B)، به انتخاب صاحب پروژه. پرامپت «زرشکی محدود» گفته بود.
- **مدل:** پیش‌فرض `claude-sonnet-5-5` با effort پایین/متوسط. Opus خودکار انتخاب نشد (پرامپت: «مدل گران را خودکار انتخاب نکن»). Haiku 5.5 ارزان‌تر است اما کیفیتش برای تحلیل دستوری فارسی سنجیده نشده؛ با تغییر `HOOSHVARE_MODEL` قابل آزمودن است.
- **fallback سمت سرور:** `fallbacks: "default"` فعال است. اگر مدل به دلیل سیاست ایمنی پاسخ ندهد، API همان درخواست را روی مدل جایگزین پیش‌فرض اجرا می‌کند. اگر نمی‌خواهید، آن را از `functions/src/index.ts` بردارید.
- **کش مشترک سرور** فقط برای شعرهای کتابخانه است. متن واردشده، گفت‌وگو و برداشت هرگز در کش مشترک نمی‌روند.
- **گزارش اشکال** در Firestore (`hooshvareReports`) ذخیره می‌شود و فعلاً فقط از کنسول Firebase قابل خواندن است.
- **پوستهٔ تاریک** طرح جدا نداشت. رنگ‌هایش از همان پالت مشتق شده‌اند.

## ثبت تجربه

قالب: رخداد؛ علت؛ راه‌حل و شاهد؛ محدوده؛ تاریخ و نسخه.

- **صفحهٔ گفت‌وگو با «destroy is not a function» از کار افتاد.** علت تأییدشده: در Chrome تازه `scrollIntoView` یک Promise برمی‌گرداند و بدنهٔ بی‌آکولاد `useEffect(() => el.scrollIntoView())` آن Promise را به‌جای تابع پاک‌سازی برمی‌گرداند. راه‌حل: بدنهٔ همهٔ effectهای تک‌عبارتی آکولاددار شد. شاهد: بازتولید و رفع در مرورگر داخلی. محدوده: هر effect با بدنهٔ عبارتی در React. تاریخ: ۲۰۲۶-۱۱-۰۱، نسخهٔ ۱٫۰٫۰.
- **ابزار نوشتن فایل، `\u` در regex را به نویسهٔ نامرئی تبدیل کرد.** رفتار درست ماند اما کد ناخوانا شد. راه‌حل: بازنویسی با escape و جستجوی نویسه‌های نامرئی در کد (نه در متن‌های فارسی). محدوده: regexهای یونیکد در `shared/text.ts`. تاریخ: ۲۰۲۶-۱۱-۰۱.
